## 三、与设计稿的已知偏差（接受，均有方案依据）

1. **今日更新行粒度**（reco）：设计稿画板为「书·章 + 新增 N 条 + 成本 chips」的逐条粒度；实现为 git log 真实流水（书名 + 更新 chip + 提交标题 + 日期·commits）。依据方案 6.2「跨书日更从 git log 抽取真实提交流水」，逐条 diff 需内容管线支持，后端 B1 落地后再对齐。
2. **主题聚合行粒度**（topic-aggregate）：设计稿画板列到条目级；实现为章节级聚合（bar+标题+书名·条数·更新）。依据方案 4.3「主题聚合页=跨书主题下全部章节」，数据模型 topicIds 挂在章上。
3. **每日一读出处**：设计稿带「书名·章节」出处；语录池（data/v2/quotes.js）暂为 v1 通用语录（无 bookId 字段），出处待 /api/v2/quotes 书源化，不伪造署名。
4. **热词内容**：热门搜索词按真实词频计算（方案 D 节），与画板示例词不同属预期。
5. **match-index 过期**：索引 676 条 < 基线 767 条（上游新增未重建索引），影响 A 占比精度与推荐覆盖，需跑 `tools/build-match-index.mjs`（其数据源 pagesA/steps.js 也待同步管线切换到 v2 基线）——属数据侧任务。

## 六、追加：细节打磨（2026-10-25 晚）

## 九、追加：iPhone 真机书架并排变一列（2026-10-25，作者反馈）

推荐页书架两张书卡在 iPhone 真机上竖排堆叠。原因：卡宽 `calc(50% - 9rpx)` + `gap: 18rpx` 相加**正好 100%**，真机子像素取整后略微超宽，被 `flex-wrap` 挤到下一行；且 `calc` 混合 `%` 与 `rpx` 在部分 iOS 上会整条声明失效（退化成内容宽）。

修复：卡宽改纯百分比 `48.6%`（留 2.8% 余量），间距改 `justify-content: space-between`（不再依赖 flex gap 的版本兼容），`min-width: 0` 防内容撑开；行间距用 `margin-bottom: 18rpx`。开发者工具与真机两列均恢复，测试 34/34 通过。

## 十、追加：分享引导蒙层不显示（2026-10-25，作者反馈）

阅读页「分享到朋友圈」引导浮层在真机上没有压暗蒙层，白色步骤字混在正文里不可读。排查定位到两个叠加原因：

1. **`inset: 0` 简写**：阅读页与结果页共 5 处蒙层用 `inset: 0` 定位，iOS 14.5 之前的 WebKit 不支持该简写 → 蒙层零尺寸完全不显示（真机白屏正文上浮白字）。全部改为显式四边。
2. **深色半透明背景在合成层不被绘制**：开发者工具实测 `rgba(0,0,0,.6)` / 近黑 / 8 位 hex / 内联样式均不渲染（红色系与不透明色正常），而结果页锁定蒙层 `rgba(23,32,28,.55) + backdrop-filter: blur` 正常 —— `backdrop-filter` 会强制合成层绘制。guide/ts/term 三个蒙层与 mine 页引导蒙层统一为 lock-mask 同款写法（近黑 + blur），顺带获得背景模糊质感。
3. **引导步骤可读性**：28rpx → 34rpx 粗体白字 + 文字投影，序号圈 36→44rpx，导航随主题（夜间下浮层同适配）。

已验证：蒙层压暗+模糊、胶囊光环高亮、步骤清晰可读（`/tmp/guide-check.png`）。test-v2 34/34 通过。

## 十一、追加：建议单条分享（2026-10-25，作者需求）

落实方案 4.3.C 的分享三级定位（book/chapter/step）：

- **条目行内分享按钮**：每个条目 NO.XX 行右侧「分享 + 收藏」双操作（均为 88rpx 命中区，负 margin 收边）。分享按钮用 `<button open-type="share" data-step>`，微信会把它携带的 dataset 传给 `onShareAppMessage`。
